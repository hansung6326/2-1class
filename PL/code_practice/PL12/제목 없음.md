#### 서브 프로그램 실행 방법

* 서브 프로그램 호출
  * 현재 실행 중인 프로그램의 상태 저장
  * sub-program으로부터 제어 변환
  * 호출한 다음 문장 실행
* co-routine
  * sub-program 종료 전에 제어를 반환할 수 있음
  * 다시 호출되면 제어가 반환된 곳에서 수행이 재개 됨
  * 호출하는 서브프로그램과 호출 받는 서브프로그램은 동등한 관계
* subroutine
  * sub-program이 종료 후 제어 반환
* 단순한 sub-program 호출 / 반환 구조
  * 실행 단계
    1. 하나의 main-program, 여러 개의 sub-program
    2. main program에서 실행 시작
    3. 다른 sub-programs 호출
    4. sub-program은 다른 sub-program을 호출할 수 있음
    5. 호출한 서브프로그램은 실행은 멈추고 호출 받은 서브프로그램이 실행을 시작
    6. 호출된 sub-program이 종료 후 제어를 반환
    7. 호출한 문장의 다음 문장에서 실행을 다시 시작
* 어셈블리 언어
  * 복사 규칙 : 호출 문장 = 호출된 sub-program을 복사/실행
  * 한계
    * sub-program의 지역 변수에 대해 하나의 메모리 장소

#### 서브 프로그램 구현 방법

* 구현
  * 고려 사항
    - sub-program = 정의 / 활성화
    - activation = code segment _ activation record
* Code
  * 실행 코드, 상수
  * 실행 중 변하지 않음
  * 메모리에 정적으로 저장됨
* Activation record
  * 프로그램 실행 환경 정보 : 지역 변수, 매개 변수
  * sub-program 호출 시 생성(할당)됨
  * sub-program 종료 시 파괴(해제)됨
* CIP (current instruction pointer)
  * 현재 명령어 포인터 = PC
* CEP (current environment pointer)
  * 현재 환경 포인터
  * 현재 실행 중인 sub-program의 activation record를 가리키는 포인터
* 단순 호출/반환 구조의 구현
  * 호출
    * CIP와 CEP activation record에 씀(저장)
    * 새로운 sub-program을 위해 CIP와 CEP를 수정
  * 반환
    * pop old IP, EP -> CIP와 CEP를 복구
* activation record 단순화
  * activation record subprogram 호출 시 생성, 종료 시 파괴 -> 실행 시간 증가
  * 가정
    * sub-program의 복사 규칙
    * sub-program은 실행 중 다른 시간에 호출됨
    * 각activation record은 다음 activation record이 시작하기 전에 삭제됨
  * 단순화하는 방법
    * 코드 세그먼트 다음에 적적으로 activation record 생성
    * 실행 중에 activation record을 생성하지 않음
    * 호출할 때마다 activation record 초기화
    * CEP는 필요없음 -> only CIP
    * FORTRAN, COBOL...
* 재귀 호출의 구현
  * 특징
    * 첫 번째 activation record이 존재할 때, 두 번째 activation record이 생성됨
    * 각 activation record은 서로 독립적
    * activation record 단순화 가정이 성립하지 않음
* 스택 기반의 activation record 관리
* 레코드 체인
  * 스택에 있는 순서에 따라 activation record 연결
  * 동적 체인
